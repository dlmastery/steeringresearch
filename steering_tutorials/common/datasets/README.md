# common/datasets/ -- the shared slices, materialised

These files are the EXACT rows most lessons draw on: not "we used
lmsys/toxic-chat" in prose, but the actual sampled prompts, their upstream
provenance, and a content-fingerprint so a reader can verify a lesson's
numbers came from these rows. Generated by
`steering_tutorials/common/export_datasets.py` via the licence-gated
`dataset_export.export_slice` (which refuses to write any gated source).

Regenerate with:

```
C:/Users/evija/anaconda3/python.exe -m steering_tutorials.common.export_datasets
```

## NON-COMMERCIAL NOTICE -- read this first

**All three slices below are cc-by-nc-4.0 (NON-COMMERCIAL)** because all are
built, wholly or in majority, from `lmsys/toxic-chat` (Lin et al. 2023,
arXiv:2310.17389, EMNLP'23 Findings). That licence is **research and
teaching use only**, and it travels with every row derived from it --
including the JailbreakBench-sourced rows in `harmful_benign_n500_s0`,
because a mixed-provenance file inherits its **strictest** term, not its most
convenient one.

## `harmful_benign_n500_s0`

- **What**: `data.build_harmful_benign(n_per_class=500, seed=0)` -- the
  course's canonical balanced binary set (`label: "harmful"|"benign"`).
- **Rows**: 1000 (500 harmful + 500 benign).
- **Composition** (this run, read from the code's own header, not assumed):
  - harmful: 500 / 500 from `lmsys/toxic-chat@0124` (toxicity==1). The
    JailbreakBench top-up path exists in `data.py` but only activates when the
    deduped toxic-chat toxic pool is smaller than `n_per_class`; at 500 the
    toxic-chat pool (693 unique after dedup) already clears it, so **the
    top-up did not fire in this run** (`extra.composition.topup_log` is
    empty). If a future re-export at a larger `n_per_class` triggers it, the
    manifest's `extra.composition.harmful` will show the split and the
    JailbreakBench rows are `mit`-licensed, but the file's declared `source`
    stays the strictest one present.
  - benign: 500 / 500 from `lmsys/toxic-chat@0124` (toxicity==0,
    length-matched to the harmful class). Benign has no top-up path in the
    code.
- **Per-row provenance**: every row carries `_source` (e.g.
  `"lmsys/toxic-chat@0124"`) and `_licence` (e.g. `"cc-by-nc-4.0"`), so
  provenance is checkable row-by-row, not just at the file level.
- **Declared licence** (`source=` passed to `export_slice`):
  `lmsys/toxic-chat`, **cc-by-nc-4.0**.
- **Fingerprint**: `30c7866a1d987fc6` (`slice_fingerprint`, order-independent
  over row content -- see `dataset_export.slice_fingerprint`).
- **Size**: 166,132 bytes gz (0.16 MB).
- **Other provenance recorded in the manifest's `extra.header`**: natural
  toxic base rate (0.0734 = 746/10165 before rebalancing), per-category
  harmful counts, per-class median char length (harmful 165 / benign 166 --
  length-matched), dedup/ambiguity drop counts.

## `concepts_150_s0`

- **What**: `data.load_concepts(n_per_concept=150, seed=0)` -- the
  per-harm-category concept split (`exemplars`/`steer`/`eval` per concept)
  used by `multi_intent`, `stacking`, and related lessons.
- **Rows**: 554 -- one row per prompt, tagged `concept` (`sexual` /
  `harassment` / `violence` / `baseline`) and `split`
  (`exemplars`/`steer`/`eval`/`baseline`).
- **Composition**: 100% `lmsys/toxic-chat@0124` -- concept category is
  derived from each toxic prompt's `openai_moderation` scores folded to a
  coarse bucket; `baseline` rows are non-toxic toxic-chat prompts. No other
  upstream source is used by `load_concepts`.
- **Kept concepts**: `sexual`, `harassment`, `violence` (each clears the
  `MIN_CONCEPT_AVAILABLE=100` gate). **Dropped**: `hate` (pool 24), `self_harm`
  (pool 27) -- too small to give an adequate 40/30/30 exemplar/steer/eval
  split, recorded in `extra.dropped`.
- **Held-out concept** (reserved for zero-shot transfer tests):
  `harassment` (`extra.held_out`).
- **Declared licence**: `lmsys/toxic-chat`, **cc-by-nc-4.0**.
- **Fingerprint**: `2ce0aadb639d4751`.
- **Size**: 60,385 bytes gz (0.06 MB).
- **NOTE -- this is a SUBSET, not `multi_intent`'s actual data**:
  `multi_intent/config.py` sets `N_PER_CONCEPT` (env
  `MULTI_INTENT_N_PER_CONCEPT`) default **"500"**, not 150. Since every kept
  concept's pool (sexual 388 / harassment 143 / violence 111) is below 500,
  `multi_intent`'s real `load_concepts` call draws the **full pool per
  concept**, not this 150-cap. Use `concepts_500_s0` below to match
  `multi_intent`'s actual config exactly; this 150 slice remains here because
  other lessons in the `USES_SHARED` family may genuinely use the 150 cap --
  check each lesson's own config before assuming which slice applies.

## `concepts_500_s0`

- **What**: `data.load_concepts(n_per_concept=500, seed=0)` -- the SAME
  concept split as `concepts_150_s0`, but at the `n_per_concept` `multi_intent`
  actually configures (`config.py`'s `MULTI_INTENT_N_PER_CONCEPT` default
  "500"). Since 500 exceeds every kept concept's pool, this call draws each
  concept's **full available pool** rather than capping at the request
  (`extra.capped_by_pool_not_request: true` in the manifest) -- `concepts_150_s0`
  is a strict subset of this slice, not an independently-drawn sample at a
  different N.
- **Rows**: 1142 (vs. 554 for the 150-cap slice -- the difference is exactly
  the extra prompts each concept's pool holds above 150).
- **Composition / kept / dropped / held-out**: identical to `concepts_150_s0`
  (same source, same concepts kept/dropped, same `held_out="harassment"`) --
  only the per-concept row count differs.
- **Declared licence**: `lmsys/toxic-chat`, **cc-by-nc-4.0**.
- **Fingerprint**: `a4ff0500474d2b52`.
- **Size**: 121,581 bytes gz (0.12 MB).

## Manifests

Each `.jsonl.gz` has a matching `.manifest.json` with the full provenance:
source, licence, `non_commercial_notice`, split/seed, row count, field list,
`slice_fingerprint`, gz byte size, and the composition/header details above
under `extra` (including, for the concept slices, `pool_sizes` and
`capped_by_pool_not_request` so a reader can tell at a glance whether a given
`n_per_concept` request was actually honored or silently capped by the
pool). All three manifests were verified by re-reading the written
`.jsonl.gz`, recomputing `slice_fingerprint`, and confirming it matches the
manifest exactly (`export_datasets._verify`).
