## 2. Findings — A. DATASET QUALITY (the primary ask)

### A-1. The lesson's motivating premise is contradicted by its own course. (highest value)

README §10 and CLAUDE.md §18.3 item 4 both assert:

> "prompt char-length is at chance, 0.5032 — **you cannot call this from the prompt alone**"

I verified this inference is wrong on two independent grounds:

1. **It is designed in, not measured.** `common/data.py` (docstring lines 45–52;
   `_length_matched_sample` at line 246, invoked at line 442; header note line 466) draws the
   benign class **length-matched to the harmful length histogram, decile-bin stratified**. A
   prompt-length AUC of 0.5032 is the sampler doing exactly what it was written to do. It is a
   *control that was applied*, not a discovery about the data.
2. **Length ≠ content.** Prompt char-length being uninformative says nothing about whether prompt
   *text* is. On the **same toxic-chat pool**, `hello_world` reports a prompt-only probe at
   **AUC 0.965** (per CONFOUND_DISCIPLINE.md §3). That is *above* every trajectory detector here
   (best 0.945).

Consequence: on this dataset a prompt-side classifier **beats** the decoding-time detector. The
verified TrajGuard abstract says its central claim is that "hidden states during decoding carry
stronger risk signals than input prompts". This lesson therefore **fails to exercise, and on its own
course's evidence contradicts, the paper's core comparative claim** — while its README asserts the
opposite from a number that was engineered to be 0.5.

### A-2. toxic-chat is the wrong prompt source for THIS lesson. (the deep question, answered)

The mechanism the paper describes needs prompts whose *surface is benign* and whose *completion turns
harmful* — that is what makes a decoding-time monitor beat a prompt-side one. toxic-chat harmful
prompts are **overtly toxic user inputs** from a live Vicuna demo. Two verified consequences:

- The abliterated model complies from token 1 (README §9 admits this: "there is no benign-looking
  preamble to hide the intent"). So the "drift" the detector is supposed to read never happens — and
  indeed `threshold_freeform`, the *drift* detector, lands at **0.638, below the 0.735 confound bar**,
  while the stateless per-token probe reaches 0.931. The lesson's own numbers say **there is no
  trajectory signal here, only a per-token one.**
- The paper evaluates on **12 jailbreak attacks**. This lesson uses **zero** attack wrappers. There
  is no jailbreak in the jailbreak-detection lesson.

Also unused: toxic-chat itself ships a **`jailbreaking` binary column** (verified on the HF card,
config `toxicchat0124`). `common/data.py` reads only `toxicity`. The disguised-attack subset the
lesson needs is *already in the pool it already loads* and is being discarded.

## 3. Findings — B. CORRECTNESS / COMPLETENESS

### B-1. The staleness hole is still open — the meerkat defect, uncured, in this lesson
- `run_trajguard.main()` line 242 calls `data.load_or_build()` **with no arguments**.
- `data.load_or_build()` (data.py:298) returns the cache **iff `cached["labels"]` is non-empty**.
  It does **not** compare against `n_per_class`, `max_new_tokens`, `LAYER`, `MODEL_ID`, or the
  `common.data` pool. The count guard `len(cached["labels"]) == expected` lives **only** inside
  `build_token_trajectories` (data.py:125), which `load_or_build` bypasses whenever a cache exists.
- Verified consequence: with `config.N_PER_CLASS = 500`, the orchestrator silently consumed the
  600-completion cache and wrote `n_harmful=300`. **That is exactly how the shipped `results.json`
  came to contradict `config.py`.** It is not hypothetical.
- There is **no pool/config fingerprint guard** — the mitigation meerkat received after its incident
  was never ported here.
- **Did the Jul-27 results come from the Jul-22 cache?** Almost certainly yes, and they are
  *arithmetically* reproducible from it (the Jul-26 `data.py` edit added `confound_report`, which is
  pure CPU numpy over the cached arrays). But **nothing records it**: no code hash, no cache mtime,
  no pool hash in `results.json`. Provenance currently rests on my reading file mtimes — precisely
  the standard CLAUDE.md §18.8 forbids ("an artifact that cannot be regenerated from the code beside
  it is not evidence").
- **A config change since Jul 22 that would alter the cache:** yes — `N_PER_CLASS` 120 → 500, visible
  in `config.py`'s own trailing comment ("was 120"). Under the current code that change has **zero
  effect** on a run with a cache present. Silent and plausible, per §18.8.

### B-2. The 106 MB artifact — verdict
- `token_trajectories.npz` = **106,095,984 bytes = 101.18 MiB**, i.e. **over GitHub's 100 MiB hard
  per-file limit**. A push containing it would be rejected outright.
- It is **NOT committed**: `artifacts/.gitignore` contains `*.npz`, and `git check-ignore -v`
  confirms the match; `git ls-files` shows it absent. The 341,673-byte sidecar
  `token_trajectories.json` is **also untracked** (matched by `*.json`), even though `results.json`
  — same pattern — was force-added.
- So the gitignore is the *right* call given the size, but CLAUDE.md §17's "binary artifacts are
  force-added so each lesson reproduces from the repo" is **violated in substance**: a fresh clone
  gets `results.json` and the PNGs but **cannot regenerate them without a GPU run**, and README §10's
  instruction — "*CPU only, no GPU, no regeneration — the trajectories are cached in
  `artifacts/token_trajectories.npz`*" — is **false for anyone who did not generate them locally**.
- Practical fix: the cache is float32 `[23022, 1152]`. `np.savez_compressed` plus float16 storage
  would land it around ~26–50 MB, under the limit and committable. Cheapest route to making this
  lesson genuinely reproducible from the repo.

### B-5. Statistical / methodological gaps (all real, none fatal at screening tier)
- **Bootstrap n = 2,000** (`config.BOOTSTRAP`), below CLAUDE.md §7's ≥10k for evaluation claims.
  Acceptable at screening tier; must rise before any external claim.
- **The margin has no CI.** `+0.209` is a difference of two AUCs on the same 600 items with no
  uncertainty attached. The correct object is a **paired bootstrap of `AUC_method − AUC_charlen`**
  over the same resample indices. Cheap, CPU-only, and it is what turns "+0.209" into a claim.
- **The CI ignores fold correlation.** Bootstrapping pooled out-of-fold predictions as i.i.d. is
  standard but optimistic.
- **The confound bar is univariate.** A logistic regression over `{charlen, tokencount, mean_norm,
  final_norm}` is the fair "all trivial features combined" bar and is not computed. The rule as
  written (worst-of-univariate) is satisfied; this would strengthen it.
- **Missing controls** vs the `hello_world` reference recipe: no label-shuffle control, no
  matched-bin stratification within `charlen` quantiles. The matched-bin check is the one that would
  actually settle whether the 0.21 margin survives at fixed completion length.
- **Early-K bar absent.** README §10 states it is required and not computed. The *streaming* claim is
  the lesson's headline, so the headline is the one number with no bar under it.
- **Not actually streaming.** `generate_and_capture` generates fully, then re-forwards the whole
  sequence. For a causal decoder the layer-12 state at position *t* depends only on ≤*t*, so the
  values are equivalent to a true streaming read — the numbers are not wrong. But no halting/streaming
  path exists. README §11 does disclose this ("Detection, not generation").
- **Detection lesson ⇒ no judge: CONFIRMED CLEAN.** No `Judge` import, no second model, no
  generation-of-a-verdict in any of the five files. `"judge": null` in the artifact.

### B-6. Things that are genuinely right (stated so the FAILs above are calibrated)
- Directionless folding implemented and used correctly (`_directionless`, data.py:230).
- The confound audit runs **before** the methods (run_trajguard.py:259), so the bar exists before the
  headline — the discipline the rule actually asks for.
- `harm_direction` and `tau` fit on **train folds only** (run_trajguard.py:284–286); no completion is
  graded on the direction it defined. Verified in code, not just claimed in prose.
- `StratifiedKFold` preserves base rate; **0 duplicate prompts** in the 600 (verified).
- `results.json` written **before** the ASCII summary print, so a cp1252 crash keeps the data.
- The runner's own summary prints "CLAIM: only the 'vs CONF' column is claimable" — the discipline is
  enforced at the point of output, not only in docs.
- README §9/§11 name the immediate-compliance confound and the abliterated-model dependency
  unprompted. That is honest reporting of the thing that most weakens the lesson.
